## Вводный текст и определение термина
Матрица в C++ — это структура данных, представляющая собой математическую сетку из строк и столбцов. Поскольку в стандартной библиотеке C++ изначально отсутствует готовый встроенный класс для матриц, программистам приходится погружаться на разные уровни реализации этой структуры — от простейших базовых массивов до сложнейших оптимизаций. 
Ниже представлена полная иерархическая карта «айсберга» матриц в C++. Каждая финальная точка (выделена жирным шрифтом) — это законченная мини-теория, строго укладывающаяся в 3 предложения.

## Теоретическая база (Строго по 3 предложения на пункт)

1.1.1. Концепция встроенных массивов Type matrix[R][C]
Статические двумерные массивы являются самым простым и исторически первым способом создания матриц в языке C++. Они выделяют память на системном стеке, из-за чего их размеры обязаны быть жестко известны еще на этапе написания кода. Главным недостатком такого подхода является высокий риск переполнения стека при попытке создать матрицу большого размера.

1.2.1. Манипулятор std::setw и заголовок <iomanip>
Для аккуратного отображения матрицы в консоли в виде ровной математической таблицы применяется заголовочный файл <iomanip>. Специальный инструмент std::setw(N) принудительно резервирует ровно N символов под вывод следующего числового элемента. Благодаря этому столбцы матрицы идеально выравниваются по правому краю, независимо от количества цифр или знаков в конкретном числе.

2.1.1. Вектор векторов std::vector<std::vector<T>>
Для создания матриц с динамически изменяемыми размерами новички чаще всего используют вложенную конструкцию стандартных векторов. Такой подход полностью безопасен, поскольку STL автоматически управляет памятью и гарантирует защиту от утечек данных при закрытии программы. Однако эта структура катастрофически медленна из-за сильной фрагментации памяти, так как каждая строка матрицы физически создается в абсолютно случайных адресах кучи.

2.2.1. Массив указателей через оператор new
Классический динамический двумерный массив создается вручную через выделение памяти под массив указателей, каждый из которых ссылается на отдельную строку данных. Этот способ заставляет программиста вручную писать вложенные циклы для очистки памяти с помощью оператора delete[]. Забытая строчка очистки или малейшая ошибка в порядке удаления мгновенно приводят к критическим утечкам оперативной памяти.

3.1.1. Формула адресации index = row * Cols + col
Профессиональные разработчики всегда хранят матрицу в виде обычного одномерного массива («линеаризируют» её) ради достижения максимальной скорости работы. Чтобы обратиться к элементу на пересечении строки и столбца, используется базовая математическая формула пересчета индекса. Этот метод гарантирует, что вся матрица будет лежать в памяти одним сплошным, непрерывным и компактным блоком данных.

3.2.1. Влияние CPU Cache на скорость обхода матрицы
Современные процессоры считывают данные из оперативной памяти не по одному числу, а целыми линейными блоками, сохраняя их в сверхбыстрый кэш. Если обходить линеаризированную матрицу строго по строкам, процессор всегда будет находить следующее число в кэше, что ускорит вычисления в десятки раз. Обход той же матрицы по столбцам заставит процессор постоянно очищать кэш и совершать долгие запросы к медленной оперативной памяти.

4.1.1. Многомерные невладеющие представления std::mdspan (C++23)
В стандарте C++23 появился революционный шаблон std::mdspan, который стандартизировал удобную работу с многомерными данными. Он сам не хранит внутри себя элементы матрицы, а лишь накладывает удобную сетку координат matrix[i, j] поверх любого одномерного буфера. Этот инструмент позволяет писать быстрый код с гибкой настройкой порядка хранения данных в памяти (по строкам или по столбцам). 

4.2.1. Библиотека стандартных вычислений <linalg> (C++26)
Новейший стандарт C++26 делает исторический шаг, внедряя полноценную поддержку линейной алгебры прямо «из коробки» через заголовок <linalg>. Эта библиотека предоставляет готовые, высокооптимизированные функции для умножения матриц, поиска определителей и сложения векторов. Синтаксис полностью построен на базе std::mdspan, что позволяет стандартным алгоритмам работать наравне с лучшими суперкомпьютерными движками.
 
5.1.1. Header-only шаблоны Eigen и библиотека Armadillo
Для профессиональных инженерных вычислений до сих пор активно используются мощные внешние библиотеки Armadillo и Eigen (p. 1). Библиотека Eigen уникальна тем, что полностью состоит только из заголовочных файлов, благодаря чему её чрезвычайно легко подключить к любому проекту (p. 1). Они под капотом используют векторные инструкции процессора (SSE/AVX), выжимая абсолютный максимум скорости из математических операций над матрицами.

5.2.1. Графический стек GLM и пиксельные матрицы OpenCV
В узкоспециализированных ИТ-сферах матрицы адаптированы под конкретные железные ограничения и типы данных (p. 1). Так, библиотека GLM применяется в игровой индустрии и 3D-графике, жестко ограничивая размер матриц рамками 4x4 для мгновенной обработки видеокартами (p. 1). В это же время библиотека компьютерного зрения OpenCV использует класс cv::Mat, где каждый элемент матрицы — это пиксель или цветовой канал загруженного изображения (p. 1).

6.1.1. Tiling/Blocking для перемножения матриц
При наивном перемножении гигантских матриц процессор начинает постоянно сбрасывать данные из быстрого кэша из-за хаотичного прыганья по адресам оперативной памяти. Профессиональная оптимизация "кэш-блокирования" искусственно делит большие матрицы на маленькие квадратные плитки (тайлы), размеры которых идеально соответствуют объему L1 или L2 кэша процессора. Программа полностью перемножает эти мелкие блоки внутри сверхбыстрой памяти процессора, что позволяет поднять общую скорость вычислений в разы.

6.2.1. Создание удобного синтаксиса A = B * C
Чтобы работать с матрицами как с обычными числами, разработчики оборачивают их в полноценные классы C++ и перегружают стандартные математические операторы. Внутри перегруженного operator* скрывается вся сложная логика вложенных циклов и проверок на совпадение размеров строк и столбцов. Такой подход позволяет писать чистый объектно-ориентированный код, скрывая низкоуровневую работу с сырой памятью за красивым математическим синтаксисом.

7.1.1. Форматы хранения CSR (Compressed Sparse Row) и COO
В реальных задачах (например, в нейросетях или физических симуляциях) часто встречаются разреженные матрицы, где 99% элементов равны нулю. Классические двумерные массивы будут тратить гигабайты памяти на хранение пустых нулей, поэтому разработчики используют форматы сжатия вроде CSR или COO. Эти алгоритмы полностью выбрасывают нули и сохраняют в памяти всего три компактных одномерных массива: массив только значащих чисел, массив их строк и массив их столбцов.
 
8.1.1. Оптимизация сложных формул вида X = A + B + C без выделения памяти
Если складывать три матрицы простым перегруженным оператором +, программа будет вынуждена создавать тяжелые временные промежуточные матрицы в памяти для хранения промежуточных результатов. Для обхода этой проблемы на самом дне "айсберга" применяется сложнейшая техника метапрограммирования — шаблоны выражений (Expression Templates). Вместо немедленного сложения компилятор генерирует ленивый шаблонный объект, который выполняет все расчеты за один единственный проход по циклу прямо в момент присваивания финальной переменной.
