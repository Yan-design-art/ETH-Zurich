1. ЧТО ТАКОЕ ЮНИТ-ТЕСТИРОВАНИЕ (UNIT TESTING)
--------------------------------------------------------------------------------
Юнит-тест (модульный тест) — это код, который проверяет работу минимально 
изолированной единицы программы (обычно одной функции или метода класса).

Главные правила:
- Скорость: Тесты должны выполняться мгновенно (миллисекунды).
- Изоляция: Один тест не должен зависеть от результатов работы других тестов.
- Повторяемость: Тест должен выдавать один и тот же результат при каждом запуске.
- Независимость от окружения: Тесты не должны ходить в реальную сеть или БД.

2. СТРУКТУРА ТЕСТА (ПАТТЕРН AAA / 3A)
--------------------------------------------------------------------------------
Каждый хороший юнит-тест логически делится на 3 шага:

1. Arrange (Подготовка): Создание объектов, настройка начальных данных.
2. Act     (Действие) : Вызов тестируемой функции/метода.
3. Assert  (Проверка) : Сравнение полученного результата с ожидаемым.

Пример структуры в коде:
TEST(TestSuite, TestName) {
    // 1. Arrange
    Calculator calc;
    
    // 2. Act
    int result = calc.add(2, 3);
    
    // 3. Assert
    EXPECT_EQ(result, 5);
}

3. БАЗОВЫЕ МАКРОСЫ GOOGLE TEST (GTEST)
--------------------------------------------------------------------------------
Google Test делит проверки на два типа:
- EXPECT_* : Нефатальная ошибка. Если проверка не прошла, тест проваливается,
             но код ИДЕТ ДАЛЬШЕ. (Рекомендуется использовать по умолчанию).
- ASSERT_* : Фатальная ошибка. Если проверка не прошла, тест ТУТ ЖЕ ПРЕРЫВАЕТСЯ.
             (Используется, если дальнейшие проверки не имеют смысла).

Основные макросы сравнения:
--------------------------------------------------------------------------------

| Проверка условия   | Мягкая (EXPECT)      | Жесткая (ASSERT)     |
|--------------------|----------------------|----------------------|
| Равенство (a == b) | EXPECT_EQ(a, b);     | ASSERT_EQ(a, b);     |
| Неравенство(a != b)| EXPECT_NE(a, b);     | ASSERT_NE(a, b);     |
| Меньше (a < b)     | EXPECT_LT(a, b);     | ASSERT_LT(a, b);     |
| Меньше/равно (<=)  | EXPECT_LE(a, b);     | ASSERT_LE(a, b);     |
| Больше (a > b)     | EXPECT_GT(a, b);     | ASSERT_GT(a, b);     |
| Больше/равно (>=)  | EXPECT_GE(a, b);     | ASSERT_GE(a, b);     |
| Истина (true)      | EXPECT_TRUE(cond);   | ASSERT_TRUE(cond);   |
| Ложь (false)       | EXPECT_FALSE(cond);  | ASSERT_FALSE(cond);  |
--------------------------------------------------------------------------------

Особые макросы:
- Сравнение строк (C-style / char*): 
  EXPECT_STREQ(str1, str2);   // Проверяет равенство строк по значению
- Сравнение чисел с плавающей точкой (float/double):
  EXPECT_NEAR(val1, val2, abs_error); // Равенство с учетом погрешности
- Проверка исключений (Exceptions):
  EXPECT_THROW(statement, exception_type); // Код должен выбросить это исключение
  EXPECT_NO_THROW(statement);              // Код НЕ должен выбрасывать исключений

4. КРАШ-ТЕСТЫ И ЧТО НУЖНО ТЕСТИРОВАТЬ (ЧЕК-ЛИСТ)
--------------------------------------------------------------------------------
Пишите тесты не только на «идеальное поведение», но и на граничные случаи:

[ ] Граничные значения (Boundary Values):
    - Для чисел: 0, 1, -1, максимальное и минимальное значения типа (INT_MAX).
    - Для строк: Пустая строка (""), очень длинная строка, строка с пробелами.
    - Для циклов и массивов: Первый элемент, последний элемент, выход за рамки.
[ ] Некорректный ввод (Invalid Input):
    - Отрицательные значения там, где ждут только положительные (например, возраст).
    - Передача нулевого указателя (nullptr) в функции, работающие с памятью.
[ ] Деление на ноль:
    - Проверка, что математические функции корректно обрабатывают или блокируют 
      деление на 0.

5. МИНИ-ШАБЛОН СБОРОЧНОГО ФАЙЛА (СMAKE)
--------------------------------------------------------------------------------
Чтобы тесты компилировались, их нужно связать с библиотекой gtest в CMakeLists.txt:

cmake_minimum_required(VERSION 3.10)
project(MyProjectTests)

# Подключение Google Test (обычно через FetchContent или пакетный менеджер)
include(FetchContent)
FetchContent_Declare(
  googletest
  URL https://github.com
)
FetchContent_MakeAvailable(googletest)

# Исполняемый файл для тестов
add_executable(run_tests test_main.cpp Calculator.cpp)

# Связывание с gtest
target_link_libraries(run_tests gtest_main)
